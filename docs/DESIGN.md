# 設計の考え方

novel_studio（小説の制作スタジオ）で確かめたことのうち、事業企画にもそのまま効くものを残し、企画に固有のことを足した。

## novel_studio から引き継いだこと

- **合議は外れ値を生まない。** 複数モデルの案は似た型に寄る（小説の企画コンペで、ミステリ 5/5 が同じ型に収束した）。分類は良し悪しではなく「型への寄り方」を見せるためのもので、外れ値を拾うかどうかは人が決める。
- **重複の判定を LLM に任せない。** AI の審判は重複の判定がぶれる。モデルには骨格の抽出だけを頼み、似ているかは道具が数える（文字 2-gram の近さ 0.4 ＋ 骨格の欄ごとの近さ 0.6、平均連結のクラスタリング）。しきい値は画面で動かせ、モデルを呼び直さずに分け直せる。
- **書式はやり直しを一回だけ。** JSON が崩れたら一度だけ直させる。費用は失敗も含めて記録する。
- **元を書き換えない。** 人が直した案・改稿した案・原案やたたきの新しい版は、すべて新しい版として足す。テーマを直すときは新しい企画フォルダを作る。

## 企画に固有のこと

### 骨格の欄
小説の「誰が欺く・何を隠す・どの層で驚かせる・何がひっくり返る」に当たるものを、事業では次の六つにした。語は選択肢から選ばせる（言い換えをさせないため）。

| 欄 | 意味 | 選択肢の例 |
|---|---|---|
| customer | 誰の | 中小製造業の経理、自治体の窓口 |
| pain | 何の課題 | 監査対応の手間、夜間の人手不足 |
| solution | 解き方の型 | SaaS／代行・BPO／マッチング／ハード＋保守／コンサル・研修／データ提供／統合SI |
| revenue | 儲け方 | 月額／従量／成果報酬／売り切り／保守／手数料／広告 |
| edge | 勝ち筋 | 価格／品質・精度／規制対応／データの蓄積／既存顧客と販路／ネットワーク効果／速さ |
| market | 市場の型 | 既存の置き換え／新しい市場／ニッチの深掘り／海外の持ち込み／制度・規制起点 |

### 数字の出どころ
事業企画で一番危ないのは、もっともらしい作られた数字。三段で抑える。
1. 素案：数字には出典か「推定」と筋道（社数×単価など）を書かせる。OpenRouter なら Web 検索で確かめさせ、URL を出典に残す。
2. 原案：確かめていない数字・仮定は「要確認事項」に「何を・どう確かめるか」と一緒に残させる。
3. たたき：原案にない数字がスライドに出たら機械で警告する（2桁以上か小数。カンマの有無は同じとみなす）。

### 字数
Issue の字数は上限として扱う。モデルは日本語の字数を数え違えやすいので 1.15 倍までは許し、それを超えたら一度だけ詰め直しを頼む。原案の字数は「目安」なので、0.6〜1.4 倍を外れたら警告だけ出す。

### モデルの割り当て
- 提案：安いモデルを並べて数を出す（発散が目的）。
- 骨格の抽出：判定がぶれない中位モデル（GPT-6 Luna Pro）。
- 原案：中身を作る工程なので上位モデル（Opus 5.5）。
- たたき：中身は原案で決まっていて、並べ替えと要約だけ。中位モデルで足りる。上位モデルだと余計な提案が増え、人の判断が揺れる。

### たたきはスライドを作らない
スライドの体裁（レイアウト・図・デザイン）は PowerPoint の Copilot や各社のアプリが得意で、しかも速く変わる。こちらは「何枚目で何を言うか」という中身の順番と、渡すための材料（Word・Markdown・Marp）と依頼文までに止める。
- Word：PowerPoint の Copilot の「ファイルからプレゼンテーションを作成」に渡す。見出し1＝1枚、見出し2＝言いたいこと。
- Markdown：Claude・ChatGPT・Gemini に、依頼文を先頭に付けて渡す。
- Marp：AI を通さずに、その場でスライドとして見る。
